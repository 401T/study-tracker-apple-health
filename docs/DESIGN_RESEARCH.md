## 1. Apple HIG の主要原則（2026-06 再掲の Design Principles）

HIG の「Design principles」は 2026年6月8日に再導入されたもので、次の8原則で構成されます（要旨）。

| 原則 | 要旨 | 本アプリでの解釈 |
|---|---|---|
| **Purpose** | 何のための製品かを常に問い、最重要機能を磨く | 「今日どれだけ勉強したか」「目標に対してどうか」を最初の1画面で伝える。機能を増やさず、記録・分析・計画の3つに集中 |
| **Agency** | 邪魔をせず、自由に動け、失敗から回復できる | 削除はソフトデリート＋「元に戻す」、インポート・復元の前に自動バックアップ。シートはいつでも閉じられる |
| **Responsibility** | 透明性と安全、データの完全性 | 端末内保存、AIは承認なしに書き換えない、読み取れない保存データは上書きしない（読み取り専用モード） |
| **Familiarity** | 既知の概念と一貫性、明確なフィードバック | タブバー・シート・グループ化リスト・セグメンテッドコントロールなど iOS 標準パターンを踏襲。トーストで結果を明示 |
| **Flexibility** | 誰にでも、多様な入力に | ダークモード、文字サイズ拡大（rem 指定）、キーボード操作、スクリーンリーダー、動きを減らす・透明度を下げる・コントラストを上げる |
| **Simplicity** | 必要なものだけ・簡潔・階層を明確に | 1カード1メッセージ。数値は大きく、単位は小さく |
| **Craft** | 細部まで丁寧に、試作と反復 | 実機相当幅でスクリーンショットを撮って反復修正（§10） |
| **Delight** | 感情の設計。ただし装飾と混同しない | 目標リングや連続日数で「積み上げの手応え」を出すが、装飾目的のアニメーションは入れない |

### Designing for iOS（要点）
- 主要タスクとコンテンツに集中できるよう画面上のコントロールを絞り、副次的な操作は最小限の操作で見つけられるようにする。
- 外観変化（ダークモード・Dynamic Type）にシームレスに適応する。
- **片手で届く画面中央〜下部**にコントロールを置く → タブバーとタイマーボタンを下部に、タイマーの主操作も画面中央に配置。

## 2. Liquid Glass の設計思想

一次資料: *Adopting Liquid Glass*、HIG *Materials*、WWDC25 Session 219 / 323。

1. **機能レイヤーとしてのガラス**: Liquid Glass はコンテンツの上に浮かぶ「操作とナビゲーションの層」を形成する素材。コンテンツ層（リスト・表・カード）には使わない。例外は、スライダーやトグルのように「操作中だけ」ガラス化する一時的なコントロール。
2. **レンズ効果（lensing）**: 従来の素材が光を散乱させるのに対し、光を曲げ・集めることで輪郭を与えつつ背後のコンテンツを見せる。
3. **鏡面ハイライトと適応**: 環境光に応じたハイライト、背景の明暗に応じた影の濃淡・色調の反転。小さな要素（バー）は明暗を反転、大きな要素は反転しない。
4. **Regular と Clear**: Regular が既定でどんな背景でも可読。Clear は写真・動画などリッチな背景の上専用で、明るい背景の上では **35% の暗幕**を検討。両者を混在させない。
5. **控えめに使う**: カスタムコントロールへの適用は最重要要素に限定。過剰適用はコンテンツから注意を奪う。
6. **ガラスの上にガラスを重ねない**: ガラス上のコンテンツは塗り・透明度・バイブランシーで表現する。
7. **ティントは主要アクションと選択状態だけ**。全要素を着色しない。
8. **同心円（concentricity）**: 角丸はハードウェアやウィンドウの角に同心で収まるよう設計。
9. **スクロールエッジ効果**: バーの下にぼかしとフェードを入れて可読性を保つ。バーに独自背景を付けない。
10. **タブバーの最小化**: スクロールダウンで縮み、スクロールアップで戻る。空いた領域にボトムアクセサリ（再生中の情報など）を置く。
11. **アクセシビリティ設定への自動追従**: 透明度を下げる → よりフロスト化・不透明に、コントラストを上げる → 白黒主体＋境界線、動きを減らす → 効果と弾性を弱める。
12. **シート**: 角丸が大きくなり、ハーフシートは画面端から内側に浮かせる。全高に展開すると不透明度が上がる。

## 3. Apple Health の情報設計に関する考察

（Apple Health の画面を複製せず、HIG *Charting data* で言及されている Health の設計と、一般的に観察できる構成原理だけを参照）

- **サマリー → 詳細** の2階層。サマリーはカテゴリ単位のカードで「最新値＋単位＋時刻」を示し、タップで詳細グラフへ。
- **カテゴリ色＋アイコン＋名称**のヘッダでカードの種類を即座に判別させる（色だけに頼らない）。
- **数値を大きく、単位を小さく**。
- 詳細グラフは **D/W/M/6M/Y のセグメンテッドコントロール**で期間を切り替え、上部に「合計／平均＋期間」の見出し、バー選択で見出しが選択値に変わる。
- HIG が明記している Health の工夫: Steps グラフは Y 軸上限が動的、各バーにアクセシビリティラベル、Trends の小グラフと詳細グラフでスタイルを一致させる。

**本アプリへの翻訳**: 「歩数」を「勉強時間」に置き換えるのではなく、勉強に固有の問い（目標達成、科目配分、計画との差、継続）をカード化した。

## 4. 今回のデザインに適用する原則

| # | 原則 | 実装 |
|---|---|---|
| P1 | コンテンツは不透明、操作はガラス | カード＝不透明 `--color-card`。ガラスはトップバーのボタン、タブバー、FAB、タイマーアクセサリ、シート、トーストのみ |
| P2 | 1カード1メッセージ | サマリーのカード: 今日／今週／科目別／継続／計画／推移 |
| P3 | 数値ファースト | `--type-metric-*` トークン（丸ゴシック系数字＋tabular-nums）、単位は subhead サイズ |
| P4 | 測定値と計算値を混同させない | 「実測」タグ、勉強時間（休憩除く）と経過時間（休憩含む）を常に分けて表示 |
| P5 | グラフは正確さ優先 | 0起点、動的上限、馴染みのある目盛り間隔、進行中の期間は淡色／点線 |
| P6 | 失敗から回復可能 | ソフトデリート、元に戻す、自動バックアップ、読み取り専用モード |
| P7 | 片手操作 | 主要操作を画面下部に配置 |

## 5. 色彩・タイポグラフィ・レイアウトの方針

- **色**: iOS のシステムカラーと同等の値を基準にした意味的トークン。背景はグループ化スタイル（ライト `#F2F2F7`／ダーク `#000000`、カード `#FFFFFF`／`#1C1C1E`）。HIG Dark Mode の「base / elevated」に倣い、シートは elevated 相当。
- **二次ラベルの濃度**: iOS 既定の secondaryLabel（60%）は白背景で約 3.4:1 と小さい文字の WCAG AA（4.5:1）に届かないため、**78% に濃くして 5.6:1** を確保（独自判断）。
- **タイポグラフィ**: HIG の iOS Dynamic Type（Large・既定）値をトークン化（Large Title 34/41 Bold, Body 17, Footnote 13, Caption2 11 = iOS の最小 11pt）。`rem` 指定でブラウザの文字サイズ設定に追従（HIG: 200% 拡大を推奨）。
- **フォント**: SF Pro は Apple プラットフォーム外での利用がライセンス上許可されないため**埋め込まない**。`system-ui` / `-apple-system` で iPhone・Mac では端末の SF Pro と ヒラギノ角ゴ が使われ、その他の環境では Noto Sans JP / Yu Gothic UI / Meiryo にフォールバック。数値には `ui-rounded`（iOS/macOS Safari で SF Pro Rounded）を使用し、非対応環境は system-ui。
- **和欧混植**: 本文の行間は 1.4（日本語で詰まりすぎない値）、`line-break: strict`、数値は `tabular-nums` で桁揃え、「数値＋単位」は `white-space: nowrap` で分割を防止。
- **レイアウト**: 4pt グリッド、iPhone マージン 16px、セーフエリア（`env(safe-area-inset-*)`）対応、900px 以上で 2 カラムのカードグリッド。

## 6. グラフとデータ可視化の方針（HIG Charting data / Charts）

| HIG の指針 | 実装 |
|---|---|
| 一般的なグラフ種類を優先 | 棒グラフ（日・週・月別）と折れ線（週間推移）のみ。科目配分は100%積み上げバー＋数値リスト |
| シンプルに、詳細は選択で | 既定は合計・平均。バーを選ぶと上部の見出しがその日の値に変わる |
| 棒グラフは0起点、範囲は動的 | `durationTicks()`：0 起点、15分/30分/1時間/2時間… の馴染みある間隔 |
| グリッド・ラベルの密度を用途に合わせる | 横グリッドは3〜4本、縦ガイドは13本以上のときのみ |
| 説明テキストを添える | 各グラフに見出し文（例「直近の週間勉強時間はほぼ横ばいです。」）と凡例（実線＝平均、破線＝目標、点線＝進行中） |
| コンパクト環境ではプロット幅を最大化、Y軸を後端に | Y 軸ラベルは右側（trailing）。左端はカード本文と揃う |
| 色だけに頼らない | 平均＝実線、目標＝破線、進行中＝淡色/点線、増減＝矢印＋符号＋文言。科目は常に名前を併記 |
| 隣接する色の間に区切り | 積み上げバーに 2px の隙間 |
| 全グラフをアクセシブルに | グラフ全体の要約ラベル＋**各バーに「日付、値」のラベル**（Health の Steps と同方針）。←→キーでバー間移動、Enter で選択、Esc で解除 |
| 同じデータの複数グラフは一貫したスタイル | すべて同じ `chart()` コンポーネント・同じ色トークン |

## 7. アクセシビリティ方針（HIG Accessibility）

| 項目 | HIG の数値・指針 | 実装・検証 |
|---|---|---|
| コントラスト | 17pt以下 4.5:1、18pt以上 3:1（WCAG AA） | `scripts/check-contrast.ts` で主要18組を検証、全て合格（§10） |
| 文字サイズ | iOS 既定 17pt、最小 11pt、200% 拡大を推奨 | Body 17px・最小 11px・全て rem 指定 |
| タッチ領域 | 既定 44×44pt、最小 28×28pt | `--tap-min: 44px`。自動走査で 28px 未満の操作要素なし（検索欄の input は 40px のラベル全体がタップ領域） |
| 要素間の余白 | ベゼル付き約12pt、なしは約24pt | リスト行・ボタン間隔に反映 |
| 色だけに依存しない | — | 前述 |
| ダークモード | 両外観で最小コントラストを確認 | ライト・ダーク両方でトークン検証＋スクリーンショット確認 |
| コントラストを上げる | 高コントラスト配色を提供 | `@media (prefers-contrast: more)` で二次ラベル・境界線を強化、ガラスを不透明＋境界線に |
| 透明度を下げる | — | `prefers-reduced-transparency` ＋アプリ内設定「ガラス効果: 不透明」 |
| 視差効果を減らす | — | `prefers-reduced-motion` でアニメーション・押下時の拡大を無効化 |
| VoiceOver / キーボード | — | ランドマーク、`aria-current`、シートは `role=dialog` + フォーカストラップ + Esc、閉じた後に元の要素へフォーカス復帰、ライブ領域でトースト通知 |

## 8. 技術的制約と代替実装

| ネイティブ機能 | Web での可否 | 本実装の代替 |
|---|---|---|
| Liquid Glass（`glassEffect` / `UIGlassEffect`）のレンズ屈折 | **不可**（ブラウザに API なし） | CSS `backdrop-filter: blur() saturate()` ＋内側ハイライト＋縁取り＋柔らかい影で「Regular バリアント」の役割を近似。**ネイティブの Liquid Glass ではない**ことを明記 |
| 押下時に内側から光る反応 | 近似可 | ポインタ位置に追従する放射グラデーション（`.glass-interactive`） |
| 背景に応じた明暗反転 | 不可（背後ピクセルの輝度を CSS で取得できない） | ライト/ダークでトークンを切り替えるのみ |
| ガラス同士のモーフィング | 不可 | 採用しない |
| SF Symbols | **ライセンス上不可**（Apple プラットフォーム向けアプリ以外での使用不可、アイコン・ロゴへの使用禁止） | 24pt グリッドの独自線画アイコンを作成（`src/design-system/icons.ts`） |
| SF Pro フォント | 埋め込み不可（同上） | `system-ui` 経由で端末側フォントを利用 |
| Dynamic Type | 直接は不可 | rem 指定でブラウザ/OS の文字サイズ設定に追従 |
| Audio Graphs（グラフの音声化） | 不可 | 各バーのラベルと要約テキストで代替 |
| `prefers-reduced-transparency` | Chromium 系のみ対応、Safari 未対応（2026-11 時点の認識） | アプリ内設定「ガラス効果: 不透明」を併設 |
| ybouane/liquidglass（WebGL） | 技術的には可能 | **不採用**（§9） |

## 9. 採用・不採用の判断

| 判断 | 内容 | 理由 |
|---|---|---|
| 採用 | ガラスは操作レイヤーのみ | HIG Materials「コンテンツ層に使わない」 |
| 採用 | タブバーのスクロール時最小化＋ボトムアクセサリ（計測中タイマー） | WWDC25 323 の `tabBarMinimizeBehavior` / `tabViewBottomAccessory` の考え方を Web で再現 |
| 採用 | シートは thick（不透明寄り）ガラス | テキスト量が多い要素は Regular（HIG） |
| 採用 | 主要アクションのみアクセント色で着色 | 「全要素をティントしない」 |
| 採用 | 独自アイコン | SF Symbols のライセンス |
| **不採用** | ybouane/liquidglass の導入 | ①要素ごとに WebGL コンテキストを生成し DOM を html-to-image（SVG foreignObject）でラスタライズするため、iPhone で電池・描画負荷が大きい ②ガラス要素はルート直下の子に限られる等の DOM 制約 ③ガラスの重なりを許容する合成で HIG の「ガラスにガラスを重ねない」と相反 ④MIT 表記はあるが LICENSE ファイル本体が無く、帰属表示の要件を満たす原文を同梱できない ⑤Muse の実行環境で WebGL・外部依存が使えるか不明。→ CSS のみの近似で移植性を優先 |
| 不採用 | Clear バリアント | 写真・動画背景が無いアプリのため |
| 不採用 | Apple Health のアイコン・画面構成の複製 | 模倣ではなく、勉強データに最適化した独自UIとするため |
| 不採用 | 装飾目的のアニメーション | HIG Delight「装飾と混同しない」 |
